# 测试计划

## 测试目标

- 确保人事核心业务流程可用、数据一致、权限可控。
- 确保后台页面在常用分辨率下可操作、可读、无明显布局问题。
- 确保接口具备校验、错误处理、审计和安全边界。
- 确保部署后服务健康检查、静态资源、API 反向代理正常。

## 测试范围

| 类型 | 范围 | 工具建议 |
|---|---|---|
| 单元测试 | 服务函数、规则计算、权限判断 | Vitest/Jest |
| 接口测试 | REST API、参数校验、错误码 | Supertest/Postman |
| 前端测试 | 表单、列表、筛选、审批动作 | Playwright |
| 集成测试 | 入转调离、考勤请假、附件、报表 | Playwright + API |
| 性能测试 | 员工分页、导入、报表导出 | k6/JMeter |
| 安全测试 | 越权、敏感字段、附件下载、审计日志 | OWASP ZAP |
| 部署测试 | Docker、Nginx、健康检查、回滚 | Shell/GitHub Actions |

## 质量门禁

- `npm run build` 必须通过。
- `npm run test` 必须通过。
- `npm audit --audit-level=moderate` 必须无漏洞。
- P0 流程测试通过率 100%。
- 不存在高危安全缺陷。
- 无阻断级 UI 问题：页面空白、关键按钮不可点、表格溢出不可操作。

## 回归策略

每次合并到 `develop` 前执行：

1. 类型检查。
2. 单元测试。
3. 核心 API 冒烟。
4. 员工档案、审批、报表页面冒烟。

每个 `release/*` 分支执行：

1. 全量功能回归。
2. 权限矩阵回归。
3. 附件上传下载回归。
4. 部署演练和回滚演练。
